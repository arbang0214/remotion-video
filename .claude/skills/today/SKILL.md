# 오늘 할 일 브리핑

`/wrap-up` 스킬이 남긴 `worklog/YYYY-MM-DD.md` 일지를 읽어, 오늘 이어서 할 일을 정리해 준다. **읽기만 한다** — 파일을 고치거나 커밋하지 않는다.

## 1. 지난 일지 읽기

- `ls worklog/ | sort | tail -5` 로 최근 일지를 찾는다.
- 가장 최근 일지는 전부 읽는다. 특히 "다음에 할 일"과 "진행 중 / 막힌 것".
- 그 전 2~4개 일지는 "진행 중 / 막힌 것", "다음에 할 일"만 훑어, 오래 미뤄진 항목이 있는지 본다.
- `worklog/` 가 없거나 비어 있으면: 일지가 아직 없다고 알리고, 메모리(MEMORY.md 와 연결된 메모)와 `git log --oneline -10` 으로 대신 추정한 뒤 "작업이 끝나면 `/wrap-up` 으로 첫 일지를 남기자"고 안내한다.

## 2. 지금 상태와 맞춰 보기

일지는 마지막 마무리 시점 기준이라 그 뒤에 바뀐 것이 있을 수 있다. 다음을 확인해 일지 내용을 갱신해서 판단한다.

- `git log --oneline --since="<마지막 일지 날짜>"` — 일지 이후 커밋이 있으면 이미 처리된 할 일일 수 있다
- `git status --short` — 커밋 안 된 작업이 남아 있는지
- 일지에서 "원본 전송 대기", "다운로드 필요" 같은 대기 항목이 있으면 `source/` 에서 해당 파일이 다 들어왔는지 확인 (전송 중이면 `stat -f %z` 를 몇 초 간격으로 두 번 재서 늘고 있는지 본다)
- 일지에 적힌 결과물이 `out/` 에 실제로 있는지 필요할 때만 확인

## 3. 브리핑

사용자에게 짧게 알려 준다. 형식:

```
지난 작업: YYYY-MM-DD — <한 줄 요약>

오늘 할 일
1. <가장 먼저 할 일> — 왜 이게 먼저인지 한 줄, 바로 시작할 파일/구간
2. ...
3. ...

확인 필요
- <대기 중이던 것의 현재 상태, 사용자가 정해 줘야 하는 것>
```

규칙:
- 할 일은 3~5개, 우선순위 순. 일지의 "다음에 할 일" 순서를 기본으로 하되, 막혀 있던 일이 풀렸거나(예: 원본 전송 완료) 이미 끝난 일이 있으면 순서를 고친다.
- 사흘 이상 미뤄진 항목은 "○일째 미뤄짐"이라고 표시한다.
- 개인정보(실명 등)는 브리핑에도 쓰지 않는다.
- 마지막에 "1번부터 시작할까요?" 처럼 한 줄로 묻고 끝낸다. 사용자가 고르기 전에 작업을 시작하지 않는다.
