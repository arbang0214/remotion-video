# 롱폼 → 쇼츠 구간 추천과 내용 파일

원본 업로드 → 받아쓰기 → 후보 추천(전체 추천 또는 사용자 지점 기준) → 사용자가 고름 → 편마다 내용 파일 → **shorts-template** 로 합성.
첫 작업: 2026-10-31 "공부 잘 시키는 부모님 특징"(17분, `universe-test/`, 내용 파일 `source/universe/ep1·2·6·7.json`). 새 편은 그 파일을 복사해 쓴다.

**역할:** 고를 구간·제목은 사용자가 정한다. 추천은 근거와 함께 표로 내고, 사용자가 번호로 고르게 한다.

## 1. 업로드

사용자는 윈도우 PC에서 맥미니로 원격 작업한다. 맥 사용이 처음이니 한 단계씩, 붙여넣을 명령어로 안내한다.

- 업로드 폴더 이름을 사용자에게 받아 **프로젝트 루트**에 만들고 `.gitignore` 에 추가한다(원본은 커밋하지 않음). 이름은 영어로(띄어쓰기·한글은 명령어가 번거로움).
- 큰 파일은 **PC의 PowerShell 에서 scp** 로 올리게 한다. VS Code 탐색기에 끌어다 놓기는 수백 MB 넘으면 끊긴다. "여기 창에 붙여넣으면 되냐"고 물으면: 아니다, 이 창은 맥미니에서 돌아가니 PC에서 PowerShell(윈도우 키 → powershell)을 따로 열어야 한다.
  ```
  scp "$env:USERPROFILE\Downloads\<파일 이름>.mp4" macmini:~/dev/remotion-video/<폴더>/
  ```
  100% 가 뜨고 `PS C:\...>` 가 다시 나오면 끝. 비밀번호 입력은 화면에 안 보이는 게 정상.
- **끝났는지 직접 확인한다** — 크기만 보면 안 된다. mp4 는 앞부분에 전체 길이가 적혀 있어 ffprobe 길이는 처음부터 맞게 나온다.
  1. 1분 동안 크기가 그대로인지(백그라운드로 기다리고, 폴링하지 않는다)
  2. 끝 몇 초에 실제 소리가 있는지: 오디오를 끝까지 뽑아 길이를 비교하고 마지막 구간 음량을 잰다
     ```bash
     ffmpeg -v error -y -i "<원본>" -vn -ac 1 -ar 16000 source/<작업>/a.wav
     ffprobe -v error -show_entries format=duration -of csv=p=0 source/<작업>/a.wav   # 원본 길이와 같아야 함
     ```
  중간에 끊긴 파일이면 사용자에게 알리고, 지워 달라면 원본과 그걸로 만든 받아쓰기도 같이 지운다.

## 2. 받아쓰기·읽기

```bash
D=source/<작업>   # git 제외 폴더
~/.venvs/whisper/bin/python source/transcribe_mlx.py $D/a.wav $D/transcript_a.json   # 17분 영상 ≈ 1분
cat $D/transcript_a.txt                                                               # [분:초] 문장
```

- 받아쓰기는 틀린다: "캐슬"→"키슬", "일희일비"→"일일 비", "찧은"→"찌은" 같은 것. 후보 표에 그대로 옮기지 말고 고쳐 읽는다.
- 원본 몇 프레임을 뽑아 화면 구성을 본다(인물 위치, 박힌 자막·로고·강조 문구). 끝부분은 보통 채널 아웃트로.

## 3. 후보 고르기 — 두 가지 방식

사용자가 원하는 지점을 함께 주면 **3-B(지점 지정)**, 아니면 **3-A(전체 추천)**. 업로드할 때 지점을 같이 말할 수도 있으니 1단계에서 "뽑고 싶은 지점이 있으면 같이 알려 달라"고 한 번 묻는다(없어도 된다).

### 3-A. 전체 추천 → 사용자가 고름

표 하나로: **순위 / 구간(분:초) / 장면 / 훅 제목 / 고른 근거**. 5~7개, 상위 2~3개에 ⭐. 길이는 1분 안팎.

좋은 후보(말로 하는 영상 기준):
- **구체적 일화**가 있는 곳(실제 학부모·학생 사례, 숫자가 나오는 이야기). 일반론만 있는 곳은 뺀다
- 반전이 있는 곳(공부 대신 운동, 장점이 약점이 되는 이유)
- 질문형 훅이 되는 한마디("아이가 엄마에게 가장 불만인 것 1위는 '불평등'")
- 학부모가 자기 경험으로 바로 공감하는 비유(최악의 부모 = 회사 최악의 상사)
- 앞뒤 맥락 없이 1분 안에 이야기가 닫히는 곳

훅 제목: 템플릿 제목 줄 수에 맞춰(대개 2줄), 학부모가 바로 알아듣는 말로. 줄 폭은 합성할 때 `--thumb-only` 로 확인(넘치면 문구를 다듬음).

공통 근거(어떤 기준으로 골랐는지)를 표 아래 2~3줄로. 그리고 주의할 점:
- 일화 속 인물이 이름 없이도 알아볼 만하면(예: "부모 둘 다 서울대", "대치동 초5 남학생") 쇼츠로 따로 떼도 되는지 사용자 판단을 받는다.
- 받아쓰기로 확인이 안 되는 말("대네비 모의고사")은 원본을 들어 봐 달라고 한다.

### 3-B. 지점 지정 → 지점마다 구간 안 제안

> 아직 실제로 써 본 적 없는 방식(2026-10-31 미리 만듦). 처음 쓸 때 어색한 점이 나오면 이 절을 고친다.

**받는 형태** — 어떤 것이든 받아서 원본 초로 바꾼다. 여러 개를 한 번에 줘도 된다.

| 사용자가 준 것 | 원본에서 찾는 법 |
|---|---|
| 시각 하나 "8분 50초쯤" | 그 시각 ±30초 문장들 |
| 범위 "13분~15분" | 그 범위 + 앞뒤 20초 |
| 내용 "팔굽혀펴기 얘기 나오는 데" | transcript 에서 낱말 검색(`grep -n 팔굽혀 $D/transcript_a.txt`). 여러 곳이면 후보 시각을 보여 주고 어느 곳인지 묻는다 |
| 영상 속 문구·장면 "‘일관성이 없는 원칙’ 자막 나오는 데" | 받아쓰기에 없으면 그 무렵 프레임을 뽑아 확인 |

시각이 유튜브 영상 기준(인트로 편집이 다른 판)일 수 있으니, 찾은 문장을 보여 주며 "이 부분 맞나요?" 를 먼저 확인한다(특히 내용과 시각이 어긋날 때).

**지점마다 구간 잡기** — 그 지점이 들어 있는 이야기 한 덩어리를 찾는다.
- **시작**: 앞 내용 없이도 이해되는 문장. "그래서", "근데", "이 친구가"(누구인지 앞에 나옴)로 시작하면 한두 문장 앞으로 당긴다. 훅이 될 한마디("~이 뭐냐면", 질문, 숫자)가 앞쪽 3초 안에 오면 좋다.
- **끝**: 결론·교훈 문장에서. 다음 화제로 넘어가는 말("그래서 두 번째는요", "실천편 해볼게요") 앞에서 끊는다.
- 지정 지점이 그 덩어리의 중간·끝이어도 된다. 사용자가 짚은 장면이 **반드시 들어가게** 잡는다.

**길이별 안 2~3개** — 같은 지점을 두고:

| 안 | 길이 | 만드는 법 |
|---|---|---|
| 짧은 안 | 30~45초 | 지점 중심 핵심만(셋업 한 문장 + 지점 + 결론 한 문장) |
| 기본 안 | 55~65초 | 이야기 한 덩어리, 반복 문장만 뺌 |
| 긴 안 | 70~80초 | 앞 맥락·뒤 교훈까지. 이야기가 길 때만 |

표: **지점 / 안 / 구간(분:초, 뺄 문장 표시) / 길이 / 훅 제목 / 근거**. 근거에는 "왜 여기서 시작·끝내는지"를 한 줄로.

**지점이 쇼츠로 쓰기 어려울 때** — 숨기지 말고 이유와 함께 대안을 낸다.
- 이야기 중간이라 앞 맥락이 길게 필요함 → 맥락을 자막·제목으로 대신할 수 있는지, 아니면 가까운 더 좋은 구간
- 같은 말 반복·일반론뿐 → 바로 앞뒤에서 일화·숫자가 있는 곳
- 화면에 학생 얼굴·실명이 나옴 → 그 부분을 빼고 잡을 수 있는지

사용자 지점 외에 근처에서 눈에 띄는 다른 후보가 있으면 표 아래 한 줄로만 덧붙인다(3-A 처럼 전체 추천으로 키우지 않는다).

사용자가 안을 고르면 4단계부터는 같다.

## 4. 고른 편마다 내용 파일

```bash
~/.venvs/whisper/bin/python source/words_mlx.py $D/a.wav 시작초 끝초 $D/words_<편>.txt   # 낱말@원본초
```

**자를 구간(parts)**
- 반복·군더더기 문장("이 말씀을 드리는 건 뭐냐면", "근데 진짜 어머니가 진짜 말했던 게 저는 아직도 기억에 남는 게")을 빼서 60~75초로. 이야기의 핵심 결론은 남긴다.
- 경계는 낱말 시각 사이(앞 낱말 끝 ~ 다음 낱말 시작) 0.1초 여유. **말과 말 사이 쉼을 줄일 때 조심** — 받아쓰기 낱말 시각이 0.2~0.3초 늦게 찍히는 일이 있어 다음 낱말 첫 글자가 잘린다("불평등"→"성등"). 쉼이 1초 남짓이면 그냥 둔다(오히려 뜸이 된다).

**자막(captions)** — 원본 시각, 한 줄씩
- 한 줄 대략 14자 이내(템플릿 자막 70px 기준 폭 980px). 넘치면 compose 가 경고 → 나눈다. 0.5초 미만으로 스치는 자막은 앞뒤와 합친다.
- 말을 짧고 자연스럽게 다듬는다: "~하더랍니다"→"~하더래요", "형성하는 가장 중요한 원인이기 때문에"→"만들어요", 맞춤법("찧었대요", "이만큼"). 뜻은 바꾸지 않는다.
- 각 자막의 핵심 낱말 하나만 `[[ ]]` 강조(모든 자막에 넣지 않는다). 직접 인용은 “ ” 로.
- 센 표현("미친 듯이 혼을 내요")은 그대로 두되 사용자에게 순화할지 묻는다.

**원본에서 쓸 범위(clean)** — 원본에 자막·강조 문구가 박혀 있으면 그 위만 쓴다.
- 박힌 자막 상자 위 끝 y 를 잰다(구간 전체를 1초 간격으로 훑어 가장 높은 값). 가끔 나오는 큰 강조 문구는 더 높이 올라온다 → 합성 후 영상 칸 아래 가장자리를 꼭 확인(shorts-template "확인").
- 같은 원본의 편들은 같은 `clean` 값을 쓴다(편마다 확대 정도가 달라 보이지 않게).
- "공부 잘 시키는 부모님 특징": 자막 상자 y≈903, 강조 문구 윗부분 y≈858 → `{"y0": 0, "y1": 846, "cx": 959}`.

**썸네일 장면(thumb)** — 그 편의 핵심 대사 무렵에서 눈 뜨고 정면인 프레임(0.25초 간격으로 뽑아 고름).

내용 파일 형식과 합성·확인은 **shorts-template** 스킬. 합성 명령:
```bash
python3 .claude/skills/shorts-template/scripts/compose.py <템플릿> $D/ep<번호>.json
```

## 5. 보고

편마다: 결과 경로·길이, 원본 몇 분 몇 초부터 어디까지, 뺀 부분(이유), **자막에서 말과 다르게 다듬은 곳 표**(말 / 자막), 강조 낱말. "처음부터 끝까지 재생 확인은 아직"이라고 분명히. 다음 편은 사용자가 고른 순서대로.

## 끝나면

- 메모리에 작업 기록(원본 위치, clean 값, 고른 편·완성 상태, 사용자 결정)을 남긴다. 일화 속 인물 정보는 적지 않는다.
- 원본·받아쓰기·내용 파일(`source/`, 업로드 폴더)은 커밋하지 않는다. 스킬·스크립트만 커밋. 하루 작업이 끝나면 `/wrap-up`.
