# 작업 마무리 + 일지 기록

하루 작업이 끝났을 때 오늘 한 일을 `worklog/` 에 남기고 커밋한다. 다음 날 `/today` 스킬이 이 일지를 읽어 이어서 할 일을 알려 주므로, **내일의 나(또는 다른 세션)가 이 파일만 읽고 바로 이어갈 수 있게** 쓴다.

## 1. 오늘 한 일 모으기

아래를 모두 확인해 사실만 모은다. 추측으로 채우지 않는다.

- 이 대화에서 한 작업, 사용자가 내린 결정, 거절하거나 미룬 것
- `git log --since=midnight --stat` 로 오늘 커밋
- `git status --short` 와 `git diff --stat` 로 아직 커밋 안 된 변경
- `ls -lt out/ | head` 로 오늘 렌더한 결과물(파일명·길이)
- `source/` 에 새로 들어왔거나 전송 중인 원본 (`find source -newermt "$(date +%F)" -type f`)
- 오늘 날짜 일지(`worklog/$(date +%F).md`)가 이미 있으면 읽어 두고, 덮어쓰지 말고 이어서 쓴다

이 대화 밖(다른 세션)에서 한 일이라 git·파일로도 알 수 없는 내용이 있을 것 같으면, 일지 초안을 보여 줄 때 "빠진 작업이 있으면 말해 달라"고 한 줄 덧붙인다.

## 2. 일지 쓰기

경로: `worklog/YYYY-MM-DD.md` (오늘 날짜, `date +%F`). 형식:

```markdown
# YYYY-MM-DD 작업 일지

## 한 일
- (프로젝트/쇼츠 이름) 무엇을 했는지 — 관련 파일·컴포지션·결과물 경로

## 결정한 것
- 사용자가 확정한 방향, 고른 시안, 거절한 안과 그 이유

## 진행 중 / 막힌 것
- 끝나지 않은 작업이 어디까지 됐는지, 무엇 때문에 멈췄는지 (예: 원본 전송 대기, 촬영 필요)

## 다음에 할 일
1. 가장 먼저 할 일 — 바로 시작할 수 있게 구체적으로 (파일, 명령, 구간 시간 등)
2. ...

## 메모
- 다음 작업에 필요한 사실 (시간 오프셋, 설정값, 주의점). 없으면 섹션 생략
```

작성 규칙:
- 한국어, 짧은 불릿. 사용자에게 보여 줄 글이므로 내부 용어보다 쉬운 말을 쓴다.
- **개인정보 금지**: 학생·학부모 실명, 연락처, 상담 내용 원문은 쓰지 않는다. "초4 학생", "학부모 A"처럼 쓴다. 이 저장소는 GitHub에 올라간다.
- `out/`, `source/`, `public/` 은 커밋되지 않으므로 그 안의 결과물은 경로와 이름만 적는다.
- 같은 날 두 번째 마무리라면 기존 섹션에 항목을 추가하고, "다음에 할 일"은 최신 상태로 고친다.

## 3. 커밋

1. 커밋 대상 확인: `git status --short`. 일지 파일과 오늘 작업한 코드(`src/`, `source/*.py`, 설정 파일 등)를 커밋한다. `.gitignore` 로 빠진 `source/`, `public/`, `out/` 은 건드리지 않는다.
2. 오늘 작업과 무관해 보이는 변경(예: 정체를 모르는 `package.json` 수정, `.vscode/`)은 임의로 넣지 말고 사용자에게 포함 여부를 묻는다. 묻는 동안 일지만이라도 먼저 커밋해도 된다.
3. 실명이 들어간 파일이 스테이징되지 않았는지 `git diff --cached` 로 한 번 훑는다.
4. 커밋 메시지: `작업 일지 YYYY-MM-DD: <오늘 핵심 한 줄>`. 코드 변경이 함께 있으면 본문에 무엇이 바뀌었는지 불릿으로 적는다.
5. 푸시는 하지 않는다. 마지막에 "원격에 올리려면 `! git push`" 라고 안내한다.

## 4. 마무리 보고

사용자에게 3~5줄로 보고한다: 일지 경로, 커밋 해시, 커밋에 넣은/뺀 파일, 내일 첫 번째 할 일.
