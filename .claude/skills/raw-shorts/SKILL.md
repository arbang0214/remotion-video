# 촬영본 → 쇼츠

카메라 원본 + 녹음 → (싱크) → 편마다 **편 설정 하나**(녹음 시각 기준) → `build.py` 가 카메라를 번갈아 붙인 중간 영상을 만들고 **shorts-template** 로 합성.
구간 고르기·훅 제목·자막 다듬기 원칙은 **longform-shorts** 3·4단계와 같다. 이 스킬은 그 앞뒤(원본 다루기·편집)만 다룬다.
첫 작업: 2026-11-06 "공부 잘 시키는 부모님 특징" 촬영본으로 7편(`source/universe_raw/`, 결과 `out/universe_shorts_raw/raw01~07`). 편집본 쇼츠와 비교하려는 목적이었다.

**역할:** 고를 구간·제목은 사용자가 정한다. 편집 판단(어디서 자르고 어느 카메라를 쓸지)은 이 스킬이 하고, 뺀 문장과 이유는 보고한다.

아래에서 `$R` = `.claude/skills/raw-shorts/scripts`, `D` = 작업 폴더(`source/<작업>/`, git 제외).

## 1. 원본 받기

- **구글 드라이브 폴더 링크:** Drive 도구로 폴더 안 파일 목록(이름·크기)을 본다(`search_files` 에 `parentId = '<폴더 id>'`). 영상은 수십 GB라 Drive 도구로는 못 받는다. 링크 공유가 켜져 있으면 curl 로 받는다:
  ```bash
  U="https://drive.usercontent.google.com/download?export=download&confirm=t&id="
  curl -sL -o $D/cam_main.mp4 "${U}<파일 id>" & curl -sL -o $D/C0903.mp4 "${U}<파일 id>" & wait
  ```
  백그라운드로 돌리고, 끝나면 **크기가 Drive 표시와 바이트까지 같은지** 본다. 받은 HTML 몇 KB 면 링크 공유가 꺼진 것 → 사용자에게 공유를 켜 달라거나 PC에서 scp 로 올려 달라고 한다(longform-shorts 1단계).
- 파일 이름에 한글·띄어쓰기가 있으면 영어로 바꿔 저장한다. 원래 이름은 메모리에 적어 둔다.
- 디스크 여유를 먼저 본다(`df -h .`). 1080p 40분 카메라 파일 하나가 16GB 정도.
- zsh 주의: `for p in "a b"; do set -- $p` 는 안 쪼개진다 → `set -- ${=p}`.

## 2. 무엇이 있는지 보기

```bash
ffprobe -v error -show_entries format=duration:stream=codec_name,width,height,r_frame_rate,pix_fmt -of compact <파일>
```
- 카메라마다 같은 시각 한 장씩 뽑아 나란히 본다 → 어느 게 넓은 화면이고 어느 게 가까운 화면인지. 길이가 똑같아도 다른 카메라일 수 있다.
- 녹음 파일(휴대폰·녹음기)이 있으면 받아쓰기는 그걸로 한다(longform-shorts 2단계). 이 받아쓰기 시각이 **모든 작업의 기준 시각**이다.

## 3. 싱크

```bash
~/.venvs/whisper/bin/python $R/sync.py $D/rec.m4a $D/cam_main.mp4 $D/C0903.mp4
```
- 카메라마다 `offset`(카메라 시각 − 녹음 시각)이 앞·중간·뒤 세 곳에서 나온다. 40분에 0.03초쯤 밀리는 건 정상 → 편마다 그 구간에 가까운 값을 쓴다.
- 일치도가 0.5 미만이면 다른 날 녹음이거나 소리가 없는 카메라 → 사용자에게 확인.

## 4. 소리 고르기

녹음 파일과 카메라 소리를 같은 40초 구간으로 비교한다:
```bash
ffmpeg -hide_banner -nostats -ss <초> -i <파일> -t 40 -map 0:a:0 -af "ebur128=framelog=quiet,astats=measure_perchannel=none" -f null - 2>&1 | grep -E " I:|Noise floor dB|RMS level dB"
```
`RMS − Noise floor` 가 큰 쪽(잡음이 적은 쪽)을 쓴다. 지난번: 녹음 31dB, 카메라 19·26dB → 녹음 파일.
음량은 build 가 -16 LUFS 로 맞춘다. **편집본 쇼츠와 비교하는 작업이면** 편집본 음량을 재서(`ebur128`) `loudness` 를 같게 맞춰야 공정하다(지난번 편집본 -21.7).

## 5. 화면 잡기

- 템플릿 영상 칸은 1080×912(가로:세로 1.184). 카메라마다 이 비율로 자를 범위 `crop [x, y, w, h]` 를 정한다. 인물 가로 중심을 구간 전체에서 5초 간격으로 훑어 잰다(`fps=1/5,tile`).
- 넓은 카메라(A)와 가까운 카메라(B)의 크기 차이를 둔다. 지난번(1920×1080 두 대, 인물 중심 x≈950):
  - A 정면 넓게 `[310, 0, 1280, 1080]`(전체 높이, 줄여서 씀)
  - B 옆 가까이 `[330, 20, 1240, 1047]` — `[410,110,1080,912]` 은 너무 꽉 차서 몸을 앞으로 내밀면 머리가 잘렸다
- 박힌 자막이 없으니 `clean` 같은 위쪽만 쓰는 처리는 필요 없다.
- 두 카메라 색이 많이 다르면 그 카메라에 `"eq": "eq=brightness=...:saturation=..."` 를 준다(지난번은 조금 달라도 그대로 둠).

## 6. 편 설정 쓰기

`$D/<편>.json` — 시각은 전부 **녹음 시각**:
```jsonc
{
  "audio": "rec54.m4a",
  "cams": {
    "A": {"file": "cam_main.mp4", "offset": 50.116, "crop": [310, 0, 1280, 1080]},
    "B": {"file": "C0903.mp4",    "offset": 49.457, "crop": [330, 20, 1240, 1047]}
  },
  "template": "daechi-navy",
  "out": "raw06_몰입형아이_부모의걱정", "out_dir": "out/universe_shorts_raw",
  "title": ["한 문제에 1시간", "몰입형 아이 부모의 걱정"],
  "parts":    [[363.18, 407.6], [411.55, 433.6]],
  "switch":   [[363.0, "B"], [371.35, "A"], [376.2, "B"], [409.0, "A"]],
  "captions": [[363.18, 366.4, "[[몰입]]을 잘하는 아이들 있죠"], ...],
  "thumb": 378.4
}
```

### 자를 곳 (parts)

받아쓰기 낱말 시각은 **0.3~0.5초 늦게** 찍히는 곳이 많다. 낱말 시각만 믿고 자르면 앞 말이 섞이거나 끝 글자가 잘린다.
1. 대략의 경계를 정하고 소리가 가장 작은 곳으로 옮긴다:
   ```bash
   ~/.venvs/whisper/bin/python -I $R/snap.py $D/a.wav 627.6 633.9 ...
   ```
   `최소`가 `말소리`보다 15dB 이상 낮으면 쉼이다. 차이가 작으면(예: 49/54) 말이 이어진 곳이라 거기서 끊으면 소리가 섞인다.
2. 쉼이 없는 경계는 고치려 애쓰지 말고 **그 문장을 통째로 빼거나 앞뒤로 늘린다**. 지난번 "이것만 시켜요 | 이분 머릿속에는"은 0.04초 단위로 옮겨도 "하지만"이 섞여서 그 문장을 뺐다.
3. 문장 끝은 넉넉히. "-더라고요"처럼 끝이 길게 끌리는 말은 소리 크기로 끝을 확인한다(낱말 시각 + 0.8초 이상일 때가 있다).
4. 말 사이 쉼이 1.5초가 넘으면 0.4초만 남기고 구간을 나눈다.
5. 쇼츠 길이는 60~75초가 기본. 이야기가 길면 80초까지, 그 이상이면 일화 속 곁가지(“왜 7분인지 모르겠어요”, 목록 나열)부터 뺀다.

### 카메라 바꾸기 (switch)

- **잘라 낸 곳에서는 반드시 카메라를 바꾼다** — 점프컷이 가려진다(촬영본 편집의 가장 큰 장점).
- 이어진 말 안에서는 문장 경계마다 5~12초 간격으로 번갈아. 한 카메라가 15초 넘게 이어지지 않게.
- 핵심 한마디(“언젠가는 되겠죠 뭐”, 결론 문장)는 가까운 카메라(B)로.
- 잘린 구간 안의 시각으로 바꿔도 된다(다음 구간 시작부터 적용됨).

### 자막·제목

longform-shorts 4단계 그대로(한 줄 14자 안팎, `[[ ]]` 강조 하나, 말 다듬기). 받아쓰기가 이상한 말(“주투키”→주특기?, “찢거나”→찍거나?)은 뜻으로 고쳐 쓰고 사용자에게 원본 확인을 부탁한다.
제목 글꼴(Black Han Sans)은 여는 따옴표 “ 가 " 처럼 보인다 → 제목에는 따옴표를 쓰지 않는다.

## 7. 만들기

```bash
python3 $R/build.py $D/<편>.json --thumb-only   # 중간 영상 + 썸네일 (제목 폭 [경고] 확인)
python3 $R/thumbs.py $D/<편>.json <scratchpad>/th.jpg 1329.0 1355.0 1380.0   # 썸네일 후보, 고른 녹음 초 → thumb
python3 $R/build.py $D/<편>.json --no-mc        # 영상까지 (자막·제목·thumb 만 고쳤을 때)
```
- 구간(parts)·카메라(switch)를 고치면 `--no-mc` 없이 다시(중간 영상 범위가 바뀜). 70초 편 기준 중간 영상 ~1분, 합성 ~1분.
- 썸네일: 눈 뜨고 정면, 가능하면 가까운 카메라. 말하는 영상이라 눈 감은 장면이 잦으니 후보 표에서 직접 고른다.

## 8. 확인 — 렌더 뒤 반드시

1. **이음새:** 결과를 다시 받아쓴다.
   ```bash
   ~/.venvs/whisper/bin/python source/clip_words.py out/.../<편>.mp4
   ```
   잘린 곳 앞뒤에 **엉뚱한 한두 음절**(“네.”, “하지만”, “반대로”)이 보이면 옆 문장 소리가 섞이거나 잘린 것 → 6장의 방법으로 고친다. 끝 글자가 바뀌면(“애매해지더라고요”→“애매해지면”) 구간 끝이 짧은 것.
   의심되는 곳은 그 주변 10초만 잘라 다시 받아쓰면 더 정확하다.
2. **화면:** 3초 간격 타일로 카메라 전환·자막 위치·머리 잘림을 본다(`fps=1/3,scale=180:-1,tile=12x2`).
3. 사용자에게: 결과 경로·길이·녹음 기준 구간, 뺀 문장과 이유, 고친 이음새, 자막에서 말과 다르게 다듬은 곳(표), 원본 확인이 필요한 말, 일화 속 인물이 드러나는지. "처음부터 끝까지 재생 확인은 아직"이라고 분명히.

## 끝나면

- 메모리에 원본 위치·원래 파일 이름·싱크 값·crop·완성한 편을 남긴다(일화 속 인물 정보는 적지 않는다).
- 원본·중간 영상·편 설정(`source/`)은 커밋하지 않는다. 스킬·스크립트만 커밋.
