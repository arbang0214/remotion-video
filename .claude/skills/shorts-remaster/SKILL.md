# 쇼츠 리마스터

채널의 기존 쇼츠를 원래 게시 순서대로, 같은 틀로 다시 만든다. 6번째 게시물로 만든 샘플(`episode.example.json`)이 기준이다.

**역할:** 디자인은 사용자가 정한다. 이 스킬의 규격(크기·색·글꼴·위치)은 사용자가 확정한 값이니 임의로 바꾸지 않는다. 규격에 없는 디자인 요소가 필요하면 지어내지 말고 묻는다.

## 준비 (처음 한 번)

- 필요한 것: `ffmpeg`, `ffprobe`, Python 3 + `pillow`, `faster-whisper`
- 확인: `python3 -c "import PIL, faster_whisper"` → 없으면 `pip3 install pillow faster-whisper`
- 글꼴 3개는 `fonts/`에 들어 있다(설치 불필요). Cafe24Ssurround(제목 전용), Pretendard-Black, Pretendard-Bold.
- 작업 폴더: 프로젝트 루트의 `remaster/epNN/` (NN = 게시물 번호 두 자리). 영상·결과물은 git에 올라가지 않는다.
- Windows에서 실행할 때만: 명령 앞에 `PYTHONIOENCODING=utf-8`, `python3` 대신 `python`.

아래에서 `$K` = `.claude/skills/shorts-remaster`.

## 작업 순서 — 단계를 건너뛰지 않는다

### 1. 몇 번째 게시물인지 묻기

작업을 시작하기 전에 **반드시** "이 쇼츠가 채널의 몇 번째 게시물인가요?"라고 묻는다. 원래 게시 순서 그대로 다시 올리므로, 번호로 강조색이 정해진다.

| 번호 (N-1)%6 | 0 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|---|
| 색 | 머스타드 #E0A526 | 아이스블루 #8FD3F4 | 테라코타 #D9825B | 민트 #9BD8B0 | 코랄 #F28B82 | 라임 #C5E063 |

예: 1·7·13번 → 머스타드, 6·12번 → 라임. 순서는 따뜻한 색/차가운 색이 번갈아 나오고, 휴대폰 채널 3칸 격자에서 비슷한 색(테라코타-코랄, 머스타드-라임, 민트-아이스블루)이 가로·세로로 붙지 않게 정한 것이다. 순서를 바꾸거나 건너뛰지 않는다.

원본 파일 경로도 받는다. `remaster/epNN/orig.mp4`로 복사해 둔다.

**화질:** 유튜브에서 받은 파일은 보통 720p로 재압축돼 있다. 같은 편의 원본(유튜브 업로드 직전 파일이나 촬영 원본)이 `out/`이나 `source/`에 있는지 먼저 찾아보고, 있으면 그걸 쓴다. 없으면 사용자에게 화질이 떨어질 수 있다고 알리고 진행한다.

### 2. 영상 내용 파악

```bash
python3 $K/scripts/transcribe.py remaster/epNN/orig.mp4        # → transcript.txt (문장 + 단어별 시각)
python3 $K/scripts/frames.py remaster/epNN/orig.mp4 overview   # → frames/overview.png (1초 간격)
```

- 받아쓰기는 틀릴 수 있다(예: "막 심화를"을 "막시마를"로, "하이레벨"을 "하이데벨"로 받아씀). 원본에 박힌 옛 자막을 overview에서 읽어 맞춰 본다.
- 영상 길이·해상도는 `ffprobe`로 확인한다.

### 3. 훅 제목 후보 제안 → 사용자가 고름

- 영상 내용을 한두 줄로 요약해 보여 주고, 제목 후보를 4~5개 표로 제안한다(윗줄 / 아랫줄 / 노림수).
- 제목은 두 줄. 학부모가 바로 알아듣는 용어를 쓴다(그냥 "심화"가 아니라 "초등 수학 심화 문제"처럼).
- **한 줄 폭 960px 이하** (Cafe24 100px 기준, 대략 10~11자). 제안 전에 실제 폭을 잰다:
  ```bash
  python3 -c "from PIL import ImageFont as F; f=F.truetype('$K/fonts/Cafe24Ssurround.ttf',100); [print(int(f.getlength(t)),t) for t in ['후보 윗줄','후보 아랫줄']]"
  ```
- 넘치면 글자 크기를 줄이지 말고 **문구를 다듬는다**(6번째 편: "많이 틀려도 괜찮은 이유"(1040px) → "많이 틀려도 되는 이유"(945px)).
- 사용자가 직접 문구를 주면 폭을 재서 알려 주고, 넘치면 다듬은 안을 제안한다.

### 4. 제목 확정 + 강조할 부분 확정 — 반드시 거친다

- 강조색은 **훅이 있는 단어**에만 칠한다. 첫 줄 고정이 아니다.
  - 예: "초등 수학 심화 문제, / **많이 틀려도 되는** 이유" → 둘째 줄 앞부분만 강조
- 강조 범위를 제안하고 사용자 확인을 받는다. episode.json에서는 `[[ ]]`로 표시한다.

### 5. 티저 썸네일 대사·장면 정하기

썸네일 = 영상의 하이라이트 순간 캡처 + 그 순간의 대사를 영상 영역 아래쪽에 크게.

- **티저 대사는 한 줄로 짧게.** 두 줄이면 위 제목과 겹쳐 정신없어 보인다. 영상 대사를 그대로 쓰지 않고 다듬어도 된다(6번째 편: "2, 3문제만 맞아도 훌륭하게 출발하는 거예요" → "**2, 3문제**면 충분합니다").
- 대사 후보 3~4개를 제안한다. 강조 단어는 같은 강조색.
- 장면: 그 대사가 나오는 구간에서 눈을 뜨고 정면을 보는 프레임을 고른다.
  ```bash
  python3 $K/scripts/frames.py remaster/epNN/orig.mp4 faces x,y,w,h 0.25   # 얼굴 영역만 0.25초 간격
  ```
  격자의 시각은 최종 썸네일과 같은 방식으로 뽑으므로 그대로 쓰면 된다.
- 대사 위치는 얼굴을 피한다. 기본은 영상 영역 80% 높이(`"y": 0.8`). 화면 한가운데는 대개 얼굴을 가린다.
- 후보 여러 개를 비교할 때는 `teaser`에 여러 개를 넣고 `--thumb-only`로 돌리면 `out/teaser_0.png …`이 나온다. 고른 뒤 하나만 남긴다.

### 6. 옛 글씨 잘라내기 (crop)

원본에는 옛 제목·자막이 박혀 있다. 그 사이 깨끗한 띠만 잘라 1080×1000에 채운다.

```bash
python3 $K/scripts/frames.py remaster/epNN/orig.mp4 still 7    # 원본 해상도 한 장
```

- 옛 제목의 아래 끝 y, 옛 자막 박스의 위 끝 y를 잰다. 자막이 길어 박스가 커지는 프레임도 있으니 overview로 가장 위로 올라온 박스를 기준으로 한다.
- `h` = 두 경계 사이(위아래 몇 px 여유), `w` = round(h × 1.08), 짝수로. `x`는 인물이 원래 구도대로 보이게(보통 가운데).
- 옛 글씨가 없는 원본이면, 원본 안에서 가장 큰 1.08:1 영역을 인물 중심으로 잡는다.
- 6번째 편(720×1280): 옛 제목 끝 y≈285, 옛 자막 위 y≈898 → `x 34, y 290, w 652, h 604`.

### 7. 자막 만들기

`transcript.txt`의 단어별 시각으로 끊는다.

- 자막 한 개 = 1~2줄, 한 줄 폭 960px 이하(Pretendard-Black 58px로 대략 16~17자). 마지막 자막은 영상 끝까지.
- **한글이 어색하지 않게 개행·띄어쓰기:**
  - 의미 단위로 줄을 나눈다. 조사·어미가 다음 줄로 떨어지지 않게 한다. 예: "이제 막 심화를 / 시작한 친구들이", "[[2, 3문제만]] 맞아도 / 훌륭하게 출발하는 거예요"
  - 맞춤법·띄어쓰기를 바로잡는다: "확인해 보세요", "줄어 가는지", 정답은 "맞히다"(맞추다 ×)
  - 반복어·군더더기는 줄이 넘칠 때 정리해도 된다("조금씩 조금씩" → "조금씩", "당장에" → "당장")
  - 말한 내용과 달라진 부분은 사용자에게 목록으로 보고한다.
- 자막 강조: 각 자막에서 핵심 단어 하나(없으면 생략)를 `[[ ]]`로 강조색 처리한다. 모든 자막에 넣지 않는다.

### 8. 빌드 → 확인 → 보고

`remaster/epNN/episode.json`을 `episode.example.json` 형식으로 쓰고:

```bash
python3 $K/scripts/build.py remaster/epNN/episode.json     # → out/thumbnail.png, out/short.mp4
```

- `[경고]`가 나오면(줄 폭 초과, 티저 두 줄) 문구를 고치고 다시 돌린다.
- 결과를 직접 확인한다. 썸네일 이미지를 열어 보고, 영상은 자막이 바뀌는 시각 몇 곳에서 프레임을 뽑아 본다(`ffmpeg -ss T -i out/short.mp4 -frames:v 1 check.png`). 확인 항목: 옛 글씨가 남지 않았는지, 강조색, 제목 고정, 자막 타이밍, 손·몸 움직임이 큰 장면. 이 확인용 이미지는 사용자에게 내밀지 않는다.
- 사용자에게는 결과물 두 개(`out/thumbnail.png`, `out/short.mp4`)의 경로와 다듬은 자막 목록만 알린다. 보정 요청이 오면 episode.json을 고쳐 다시 빌드한다.

## 고정 규격 (build.py에 들어 있음)

| 항목 | 값 |
|---|---|
| 화면 | 1080×1920. 위 바 0~480, 영상 480~1480 (1080×1000), 아래 바 1480~1920. 바 색 #0A0A0A |
| 제목 | 2줄, Cafe24Ssurround 100px, 흰색 + 훅 단어만 강조색. 세로 중심 290 / 410. Cafe24에 없는 글자는 Pretendard-Bold로 자동 대체. 영상 끝까지 고정 |
| 프로필 | "이강준 · 카박준쌤" Pretendard-Black 46px 흰색 / "KAIST 박사 · 대치동캐슬 초등수학" Pretendard-Bold 32px #9A9A9A. 썸네일에는 항상, 영상에서는 자막이 없는 구간에만(자막이 있으면 빼기 — 어차피 유튜브 UI에 가려짐) |
| 자막 | 아래 바, Pretendard-Black 58px 흰색, 첫 줄 중심 1550, 줄 간격 78 |
| 티저 대사 | 썸네일 영상 영역 안, Pretendard-Black 76px 흰색 + 검정 외곽선 6px, 한 줄 |
| 썸네일 선생님 화면(선택) | 실시간 수업 시리즈에서 썸네일 장면에 선생님이 없을 때. teaser 항목의 `"pip"`. 영상 칸 오른쪽 위(여백 16), 폭 520px, 흰 테두리 4px. 썸네일에만 |
| 배지(선택) | 실시간 수업 시리즈(9번째 편~)만. "● 실제 수업 영상" — 제목 위 가운데(세로 중심 170), 진회색 #2A2A2A 알약(높이 64) + 빨간 점 #E5484D, Pretendard-Black 40px 흰색. 썸네일·영상 모두 |
| 출력 | H.264 CRF 16, 30fps, AAC 192k. 오디오는 원본 그대로 |

## episode.json

```jsonc
{
  "post_no": 6,                         // 채널 게시 순서 → 강조색
  // "badge": "실제 수업 영상",          // 선택: 실시간 수업 시리즈 편에만 넣는다
  "source": "orig.mp4",                 // episode.json 기준 경로
  "title": ["초등 수학 심화 문제,", "[[많이 틀려도 되는]] 이유"],
  "crop": { "x": 34, "y": 290, "w": 652, "h": 604 },   // 원본 픽셀 기준
  "captions": [ { "from": 0.0, "to": 1.28, "text": "이제 막 심화를\n시작한 친구들이" } ],
  "teaser": [ { "time": 5.5, "text": "[[2, 3문제]]면 충분합니다", "y": 0.8 } ]
  // 선택: teaser 항목에 "pip": { "source": "orig.mp4", "time": 68.5, "crop": { "x": 80, "y": 94, "w": 562, "h": 308 } }
  // 선택: teaser 항목에 "time" 대신 "still": "thumb/still.png" — 미리 합성한 영상 칸 이미지(1080×1000). 표정 좋은 장면과 채팅 장면을 합칠 때(ep11/thumb.py)
}
```

전체 예시는 `episode.example.json`.

## 아직 정하지 않은 것

- 재업로드 방식(새로 올리고 기존 편 비공개 / 삭제 / 기존 편 썸네일만 교체)은 전체 리마스터 결과를 본 뒤 사용자가 정한다. 업로드는 이 스킬이 하지 않는다.
